## 三、已发现并修复的问题（回归记录）

| 问题 | 根因 | 修复 |
| --- | --- | --- |
| 点击通知已读后卡片样式不更新 | Vue 3.5 中 reactive 数组读方法（find 等）返回 raw 元素，改其属性不触发渲染 | 用索引整体替换元素 `list[idx] = { ...list[idx], isRead: true }` |
| 匹配页对方物品只显示「物品 #4」 | 接口仅返回 lostItemId/foundItemId | 前端批量补拉对方物品的标题/描述 |
| 匹配页「返回列表」点击报错 | 模板绑定了不存在的 `backToList` | 补上实现：跳转 `/items` |
| 拾物发布者也能看到确认/拒绝按钮，点击 403 | 按钮只按「发布者本人」判断，未区分失物/拾物 | `canOperate` 增加 `type === 'lost'` 判定，仅失主可见 |
| 首页直接解构 `list`，后端换分页对象会白屏 | 未做分页形态归一化 | 改用 `normalizePage` |
| 认领成功后按钮仍可点击，重复提交报 409 | 成功后未更新按钮状态 | 成功后按钮变「已申请」禁用；收到 409 时同样切换并提示 |
| 通过时只填时间或只填地点被静默丢弃 | 未做成对校验 | 校验时间/地点必须同时填写或都不填 |
| /publish 与 /items/:id/edit 切换时表单不刷新 | 两条路由复用同一组件实例 | `watch` 路由 fullPath 重新初始化表单，并做竞态保护 |
| 交接详情缺双方信息 | 接口只返回 itemTitle/itemId | Mock 与页面补充发布者、认领人信息 |
| 驳回没有理由输入 | 直接 confirm 后调接口 | 驳回改为必填理由的输入弹窗，`reason` 随请求提交 |
| 离开详情页后「已申请」状态丢失 | `claimed` 仅存在当前页面内存 | 进入详情页时查一次 `/claims/mine` 按 itemId 判断，并 watch 路由参数重新加载 |
| HTTP 4xx 时页面拿不到 `e.code` | 错误拦截只处理了 HTTP 200 的业务错误 | 错误分支补 `error.code = body?.code ?? response.status`，并把后端 message 挂到 `error.message` |
| Mock 对匿名用户也返回联系方式 | `enrichItem` 未区分登录态 | 联系方式仅对已登录请求返回，与详情页展示逻辑一致 |
| 联系方式三档未按角色裁剪 | Mock 只做了匿名隐藏 | 按 api.md §4：发布者/管理员/已通过认领人完整，其他登录用户脱敏 |
| 列表筛选参数与契约不符 | 前端传 `category`/`location` | 改为 `categoryId`/`locationId`（api.md §1） |
| 交接详情无权限控制 | Mock 直接返回数据 | 非认领人/发布者/管理员返回 403，页面给出明确提示（api.md §6） |
| approve 与交接是两步独立请求 | 通过后再单独调 handovers | 改为 approve 一次提交可选 handTime/place，Mock 单事务处理；只传一个返回 400（api.md §3） |
| 补登记重复创建交接 | 未校验已存在交接 | 已登记过交接的认领再登记返回 409（补登记仅限「仅通过」场景） |

## 四、契约同步情况

api.md 已确认契约（§1~§9）中，前端已完成同步：

- §1 列表/筛选/分页：`categoryId`/`locationId` 参数与 `{list,total,page,pageSize}` 形态 ✓
- §3 审核通过单事务：approve 一次提交可选 handTime/place ✓
- §4 联系方式三档可见性 ✓
- §5 驳回理由：reason 必填提交 ✓
- §6 交接详情权限（403）与双方字段 ✓
- §8 匹配操作仅失主可见 ✓

剩余待跟进（不阻塞联调）：

1. §7 物品详情 `myClaim` 字段：ItemDetail 应改用 `myClaim` 初始化「已申请」按钮，替代现在的 `/claims/mine` 查询。
2. §9 图片上传接口：发布页目前仅本地预览，联调时接上传。
3. §2 分类/地点公开接口（`/categories`、`/locations`）：下拉选项暂用与 `database/seed.sql` 一致的固定值，联调时换为接口获取。
